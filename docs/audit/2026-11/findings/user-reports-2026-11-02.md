### UR-3 — partially-confirmed, bug P2
- **Observed:** The merge itself is fine. Device B, having only seen the review, takes A's done (state done plus doneAt). The leaf-conflict cases keep each device's own value: B's 'folded' against A's 'done', and B's 'skipped' against A's 'done'. In the app, the review auto-opened about 1.5 s after the reload (isOpen true, slot morning, seenAt written). The cloud cycle only starts after BOOT_DELAY of 3 s plus the network. When 'done' arrived, due() went to null and recent() reported done, but the open sheet stayed on screen (sheetStillOpen true; screenshot). Pressing its 'Skip review' rewrote the slot to state 'skipped' (skippedAt added beside A's doneAt). Because only B changed that leaf against the base, the next merge sends 'skipped' back to A.
- **Root cause:** The state does carry across: state.dayReview.days is a synced keyed map and merges per leaf. The bug is ordering. (1) Auto-open decides from local state before the first pull of the open, at 1.5 s at boot and 600 ms after returning, against a pull at 3 s plus the network, or one skipped entirely within MIN_PULL_GAP. So the second device shows a review the first already finished. (2) Nothing reacts to a pull that closes the review: an open sheet stays open, and the chip only repaints every 30 s. (3) The sheet's finish writes blindly, so Skip on the stale sheet turns the other device's 'done' into 'skipped', and that propagates. The per-device ui.review.lastShown/minimised fields (state.ui) are correctly not synced.
- **Fix / what it would take:** (a) Hold auto-open until the first cloud cycle of this open has finished, or time out (say 4 s), when signed in. Have the cycle that ends call KOS.reviewSheet.maybeOpen. (b) After any pull, repaint the chip. If the open sheet's slot is now closed (done or skipped) on the merged state, close it with a short note ('Finished on another device') or turn it into the 'opened again' mode. (c) In dayReview.finish, never downgrade: a 'done' slot stays done, so 'skipped' is ignored when the stored state is 'done'. Optionally, add a merge rule that a closed state beats 'folded' and 'done' beats 'skipped'. (d) Add a smoke test with two docs that checks the sheet closes after the merge.
- **Not verifiable in the harness:** There is no second real device or live Supabase pull in the harness. I simulated the other device's write by setting the merged leaf directly. The timing race (1.5 s against BOOT_DELAY plus network) comes from the code constants, and real iPhone or iPad network latency will vary.

### UR-5 — partially-confirmed, bug P2
- **Observed:** The clock does not stop while the page is only frozen. Elapsed time is wall-clock (now - phaseStartTs), so on wake the screen-off time counts as focus: A gave 45 min after 5 real minutes plus 40 asleep, still running. Three side effects showed up. (1) Every lock during a work phase is logged as a distraction: 1 after A, 2 after B, and from the second onward −2 HP when the penalty is on, with a 'Distraction #n logged' toast on return. (2) If the first tick after wake runs before visibilitychange (the order is not guaranteed on iOS), the idle watch fires its 'Still studying?' warning: idleWarnedAt was set, and a focus notification was pushed into the bell, though the visible event cleared it straight away. (3) If the page keeps running while hidden, the idle watch ends the session at 35 min (state idle, ended 'idle'). The case that matches 'the timer stopped' is restore after iOS discards the page: the session comes back PAUSED ('Focus session restored — 50 min kept, paused where you left it', restores 1; screenshot). It is credited only up to lastBeat, so the asleep time after the last heartbeat is lost.
- **Root cause:** Invariant 4c makes 'recovery returns paused' intended for a reload or crash, and that is what a discarded iOS page goes through. Invariant 4d makes the idle end intended for an untouched page. But neither rule tells a deliberate screen lock apart from leaving the app: a phone's auto-lock is charged as a distraction, and a long lock that ends in iOS discarding the page loses the asleep time and returns paused. That reads to the user as the timer stopping. The frozen-page path itself is correct: the time is recomputed from wall clock on return.
- **Fix / what it would take:** (1) On visibilitychange hidden, bank the clock and write lastBeat = now synchronously (as bankForUnload does) so a discard after a lock loses nothing up to the lock. (2) In restore(), when the snapshot was running and the gap since lastBeat is under a cap (say ≤ 3 h, or bounded by the idle rule), offer 'Count the time the screen was off (N min)?' instead of silently dropping it, or credit it under the idle rule: up to IDLE_WARN past the last activity, then the 4d rule. (3) Do not count a hidden period as a distraction when it ends with no other page shown, or add a phone default 'Screen lock is not a distraction'. At minimum, let the user set the penalty from the running screen. (4) Run idleCheck only while the page is visible, or call noteActivity before the first tick after a visibility return, so wake order cannot warn spuriously. (5) Optionally keep the screen awake while Focus runs on a phone (KOS.desk's wake lock is already used for Focus; check it is re-acquired after visibility, see EX-18). Run a real-iPhone test before closing.
- **Not verifiable in the harness:** Headless Chromium cannot lock a screen, freeze JS the way iOS does, discard a page under memory pressure, or show whether iOS standalone PWAs fire pagehide or pageshow on lock. I modelled those states by faking Date.now and visibility and by restarting the browser. Whether the user's 'stop' was a discard and restore, the idle end, or a missing wake lock needs a test on a real iPhone (stopwatch, lock 10 and 45 min, return).

### UR-6 — qol-recorded, qol 
- **Observed:** Today a running Focus session is deliberately per device (invariant 33b): another device never sees it. A routine's step timer is not persisted even on its own device, so a reload loses it. Nothing offers handoff.

### UR-7 — confirmed, bug P1
- **Observed:** Every clip with maths draws each formula twice: KaTeX's MathML layer as a second line under the visual layer ('a^m × a^n = a^{m+n}' then 'am × an = am+n'). Fractions and roots break apart (the 1/(2√2) in the table falls into loose pieces). Because the duplicated, unstacked content is taller than the original, the picture is cut off at the block's on-screen height: the callout stops at '(ab)^n = a^n b^n and', and the table keeps only half of its first row out of three. Separately, clipping when a new page has to be made repaints the whole tab, and the notes pane jumps back to the top (scrollTop 3069 to 0, the notes node replaced).
- **Root cause:** picture() clones the block into an SVG foreignObject and inlines only the properties in PROPS, then removes every class. KaTeX hides its .katex-mathml layer with position:absolute, clip, height:1px and overflow:hidden, and it stacks fractions, sub/superscripts and roots with position:relative plus top offsets and fixed heights. None of those are copied, so the hidden MathML text appears and the vlists collapse. KaTeX's web fonts are not reachable inside an SVG used as an image, so the fallback metrics differ too. The foreignObject keeps the original height, so the taller result is clipped. A table inside a horizontal scroller is also clipped to its visible width. Clipping onto a new page repaints the tab through addPage, which calls paint() whenever the view is not 'page' (line 199). Minor: picture() has no guard for a 0x0 rect, so a detached block stores an item with src 'data:,' at 0x0. This happened in the harness with a stale node.
- **Fix / what it would take:** Rasterise differently. Either drop .katex-mathml (and any sr-only or aria-hidden nodes) from the clone and copy position, top, left, right, bottom, height, min/max sizes, vertical-align, overflow and clip, or better, render the block with a DOM-to-canvas path that embeds the KaTeX fonts as data: @font-face inside the SVG. Measure the clone's scrollWidth and scrollHeight (not the on-screen rect) for the SVG size, and unwrap a .k-n-tablescroll so the whole table is captured. Refuse w or h of 0. In addPage, when view is 'side', append the new sheet into the right pane instead of calling paint(), so the notes keep their scroll. Add a smoke that clips a maths callout and checks that the image height is at least the block's scrollHeight and that the clone holds no .katex-mathml.
- **Not verifiable in the harness:** Headless Chromium can read the canvas back, so the stored clip is a PNG. iPad Safari taints the canvas and keeps the SVG data URL (inktab.js:88-97), but that SVG is built from the same clone, so the duplication and the cut-off should be the same or worse there. Not checked on a real iPad or with the Pencil.

### UR-8 — confirmed, bug P2
