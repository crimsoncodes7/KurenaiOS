# AQA 7516 (AS) Paper 1 — examiner's report notes

Paraphrased from AQA's *Report on the Examination* (saved in your folder by
`tools/fetch_reports.py`), in our own words, citing series and question.
The AS paper's habits carry straight into A-level Paper 1 Sections B–D.

---

## Habits both years repeat

- **An identifier is just the name**: `LoadPuzzleFile`, not
  `def LoadPuzzleFile` or `LoadPuzzleFile()`; no data type with a
  variable. Extra code lost the mark every year.
- **Paste the whole edited subroutine** as text, so the examiner can see
  where new code went. A capital letter should be at least 2 mm high
  when the EAD is printed.
- Screen captures not made by your own code score nothing.
- A "describe" mark needs the reason: "reduces testing time" scored
  nothing, but "…because there is less code to test" did.
- A definition mark needs a standalone definition, not "the opposite of
  the last one".
- Don't say the same point twice in different words for a two-mark
  question.

## June 2022

### Q01 (5) · 4.4.1.2 trace table
- The usual dropped mark was the last one: **state the result** the
  algorithm produces.

### Q02 (6) · 4.4.2.1 labelling an FSM
- 48% full marks. Trap: assuming one label per cell when the question
  said some need more than one.

### Q03.1 (8) · 4.1.1.8 random integers
- Traps: the wrong syntax, or the wrong range (0–6 for 1–6 inclusive).
  Later marks were still earned with a fixed value in place — keep going.

### Q06.2 · a structure's roles
- It had several roles; most named one. Count the marks.

### Q08 · decomposition
- "Breaking a problem into sub-problems" alone got one of two. It applies
  to the **problem**, not the solution; the spec's own definition helps.

### Q09.1 · definite vs indefinite iteration
- Define each on its own: definite runs a number of times known before it
  starts; indefinite runs until a condition is met.

### Q10.1 · exception handling
- "Stops a crash" is one mark; the other is that it handles **run-time**
  errors. "Errors" alone wasn't enough.

### Q11.1 · subroutine
- "A named section of code" alone was incomplete: it is a named block
  that performs a specific task and can be **called** from elsewhere.

### Q12 · protected coordinates (first modification)
- New checks go **after** the existing integer-conversion validation.

### Q13 · Sudoku-style validation (six marks)
- Row and column were easy (two loops); the **sub-grid** check (MOD with
  nested loops, or a nine-way selection) was the discriminator.

### Q14 · undo
- Students split into those who stopped after the call and those who
  finished. Traps: an empty string instead of a space; assuming the
  number of undos is one digit (−10 read as −1 then 0).

## June 2023

### Q01 (6) · 4.4.2.1 state transition diagram
- Again: some states needed more than one label.

### Q02 (5) · 4.4.1.2 trace table
- Under 40% full marks; the usual error was the right value in the
  **wrong column**.

### Q03 (2) · 4.1.1.13–14 global vs local
- Under half got both. "Local has less scope" is too vague: local exists
  only inside its subroutine while it runs; global is visible to the
  whole program for its whole run.

### Q04 (2) · 4.4.1.2 what an algorithm is
- Most scored nothing: "a set of instructions" isn't enough. A sequence
  of steps that can be followed to complete a task, and that always
  terminates.

### Q05.1 (9) · 4.1.1.2 pseudocode → code
- About 90% got 8–9. The dropped mark: the selection's logic **reversed**.

### Q11 · three questions on one subroutine
- Marks were lost by putting a right answer under the **wrong part**.
  Read each part's ask.

### Q12.1 · first modification
- The forgotten step was updating the status register.

### Q13.1 · validating a line number
- Trap: a **hard-coded** upper bound. The program's length varies; use
  its length.

### Q14–Q15 · later modifications
- Q14 was the most skipped, yet three quarters of attempts scored 3–4 of
  4, with approaches the scheme hadn't foreseen still credited.
- Q15: marks came for the menu change and input handling even when
  insert or delete was unfinished. Attempt it; then attempt its matching
  screenshot.
