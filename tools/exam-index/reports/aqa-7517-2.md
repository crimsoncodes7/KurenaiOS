# AQA 7517 Paper 2 — examiner's report notes

Paraphrased from AQA's *Report on the Examination* for each series (saved
in your folder by `tools/fetch_reports.py`). Every point is in our own words
and cites its series and question. Marks and leaves come from the index.

---

## June 2022

### Q01.1 (2) · 4.5.2.1 number bases — binary → hex
- Asked: *describe* how to convert binary to hex.
- Most: did the conversion instead of describing it (no marks), or said
  "split into 4-bit groups" then described each group's value vaguely.
- Marks: split into nibbles from the right (1); each nibble → one hex
  digit, with how (1).

### Q01.2 (1) · 4.5.2.1 why hex, not binary
- Trap: "hex uses fewer digits to store". It is always STORED in binary;
  hex is only shorter to read and write for humans.

### Q02.1 (2) · 4.9.1.1 parallel transmission
- Most got "several wires"; the second mark needs **one bit per wire, at
  the same time** — "data/packets sent together" was too vague.

### Q02.4–Q02.5 (1+1) · 4.9.1.2 start and stop bits
- Poorly understood. "Shows where the transmission starts/ends" scored
  nothing.
- Start bit: wakes the receiver and **synchronises the receiver's clock
  with the sender's** — name both clocks.
- Stop bit: lets the next start bit be recognised / gives the receiver
  time to process the byte.

### Q03.3 (4) · 4.6.5.1 Boolean simplification
- Only about a quarter got full marks.
- Trap 1: simplifying A + Ā to 1 when the A was ANDed with (B + 1) —
  **AND binds tighter than OR**; respect precedence first.
- Trap 2: applying De Morgan across mixed operators in one step. It only
  extends to several operators at once when they are **all the same**.

### Q04.3 (2) · 4.6.1.4 functions of an operating system
- Naming a function ("memory management"), even in a sentence, scored
  nothing. Describe it: *regions of memory are allocated to processes*.
- "Provides a user interface" needs developing: the OS is a layer that
  hides the hardware's complexity.

### Q05.1 (2) · 4.5.4.4 fixed point → decimal
- Traps: treating the −32 place as +32; or writing −20 and .6875
  separately as −20.6875. It is −20 **+** 0.6875 = −19.3125.

### Q05.2 (2) · 4.5.4.8 why normalise
- Vague answers ("more accurate", "easier to read") scored nothing.
- Marks: **maximum precision** for the bits available; **one unique
  representation** per number (so equality tests are simple).

### Q05.3–Q05.4 (2+3) · 4.5.4.4 floating point
- Traps: moving the point the wrong way; exponent sign (+9 for −7).
- Negative values: write the positive in fixed point first, THEN take
  two's complement. Writing "−23" then "+.25" gives −22.75.
- **Show working** — it earns credit when the final answer slips.

### Q05.5 (2) · 4.5.4.5 relative error
- Traps: a negative absolute error; dividing by the stored value instead
  of the true one; arithmetic slips.

### Q06 (12) · 4.7.4.1 + 4.8.1 bar codes, RFID and a loyalty scheme
- Covering only two of the three areas capped the level.
- Legal/ethical: consent, GDPR duties, who sees the data and for what.
  Don't assume data was taken without consent.
- Misconception: a bar's colour is a bit. Bars differ in **width**.

### Q07.2 (2) · 4.10.1 ER degrees
- Trap: drawing one-to-one because an animal is in one place *now* — the
  data kept history, so it was one-to-many. Read what the table stores.

### Q07.3 (3) · 4.10.4 CREATE TABLE
- Under a quarter full marks. Traps: data type before the field name;
  missing commas between field definitions. Syntax must be exact.

### Q07.4 (7) · 4.10.4 SELECT with a date range
- Structure and the join condition were usually right; the date
  conditions that catch **every** overlapping stay were the hard part.

### Q07.5 (2) · 4.10.3 adding a redundant attribute
- Advantage: one-table query, no join. Disadvantage: redundancy →
  extra storage → possible **inconsistency** and harder updates.

### Q08.1 (3) · 4.9.2.2 peer-to-peer vs client-server
- Misconceptions: all traffic passes through the server; if the server
  fails the network fails. Neither is true.

### Q08.2 (3) · 4.9.2.2 which suits a student house
- Use the context (few devices, users trust each other, choose what to
  share). "Cheaper" needs the why (no server to buy).

### Q08.3 (3) · 4.9.3.1 DNS
- "Addresses" without "IP" scored nothing. Better: FQDN → IP; a hierarchy
  of servers holding a distributed database; unknown names are forwarded.

### Q09.2 (5) · 4.7.3.5 assembly trace
- Under a quarter full marks. Traps: LSR shifted left; a fractional value
  after a right shift; forgetting the final STR to memory.

### Q09.4 (2) · 4.6.2.1 why write in assembly
- Faster or smaller code. Not "doesn't need translating" (it does) and
  not hardware access when the task doesn't need it.

### Q10.1 (3) · 4.5.6.7 sound duration
- Trap: MB → bytes as ×1,000 instead of ×1,000,000.

### Q11 (3) · 4.9.4.11 thin vs thick client
- Only about a third scored. "Powerful server", "cheap computer" are not
  A-level answers — say RAM, cores, storage, and **which machine**.

### Q12.3–Q12.4 (4+1) · 4.12 functional programming
- Write a list result **in brackets**. Tracing the recursive functions was
  the discriminator; the purpose must be specific (average °C from a list
  of °F, not "averages a list").

### Q13.2 (2) · 4.7.4.2 why secondary storage
- "Non-volatile" alone or "more storage" alone scored nothing — explain.
- Misconception: main memory is volatile (ROM isn't); secondary storage is
  a backup of RAM (it isn't).

## June 2023

### Q01.1 (2) · 4.5.6.7 sound file size in MiB
- Usually 1 of 2. Traps: ÷1000 instead of **÷1024** for mebi; forgetting
  **÷8** to go from bits to bytes.

### Q01.3 (1) · 4.5.6.1 what turns binary into a waveform
- About half wrote ADC. Playing sound back is a **DAC**.

### Q02.1 (2) · 4.9.4.1 packet fields
- Most named one field; only about a quarter named two (e.g. source and
  destination IP, sequence number, TTL, checksum, payload).

### Q02.2 (2) · 4.5.5.3 checksum
- Vague: "checks the data is correct" / "an algorithm on the data".
- Marks: detects data **changed in transit**; computed from the payload
  by a calculation the receiver repeats. (It can't prove the data was
  right when sent.)

### Q02.3 (2) · 4.9.3.1 a router's role
- "Sends it to its destination" was too thin. Routing is **hop by hop**:
  each router picks the next hop for the packet.

### Q03.1–Q03.3 (1+1+1) · 4.5.6.10 Caesar and substitution ciphers
- Caesar: the slip was the last letter wrapping round past Z.
- Shared weakness: a letter always maps to the same letter, so
  **frequency analysis** works. "Few keys / brute force" isn't shared
  (the substitution cipher has many keys).
- Avoid "random" unless you mean it; "more random" scored nothing.

### Q03.4 (2) · 4.5.6.10 Vernam perfect security
- Say "**the key** is used once / truly random / as long as the
  message", not "it".

### Q04.1 (12) · 4.7.3.2 + 4.7.3.7 fetch–execute and performance
- Weakest stage was **execute**; fetch got most detail. Cover all three
  stages with the registers.
- Be precise on improvements: more cores means instructions run
  **simultaneously**, not just "more per second".

### Q04.2 (2) · 4.7.3.6 interrupts
- Define it: a signal from a device or program asking for the
  processor's urgent attention. It does not stop the fetch–execute cycle
  (it is checked at the end of each cycle), and it is not about
  instruction priority.

### Q05.1 (5) · 4.10.3 completing a normalised design
- Traps: a redundant ScreenNumber in Booking (it follows from
  ShowingID); one relation for a booking of several seats (needs two).

### Q05.2–Q05.3 (2+2) · 4.10.4 DELETE and integrity
- The errors: an unneeded table in the query; the date **unquoted**.
- Deleting showings with bookings breaks **referential integrity** /
  foreign keys — use the terms.

### Q05.4–Q05.5 (1+1) · 4.9.4.10 REST and CRUD
- Weak area. The URL causes a query on the server. GET→SELECT,
  POST→INSERT, PUT→UPDATE, DELETE→DELETE.

### Q06.1–Q06.2 (2+3) · 4.5.4.4 floating point
- Same traps as 2022: point moved the wrong way (6.5 for 13/128);
  −23 then +.25 giving −22.75. Convert the positive, then negate.

### Q06.3 (2) · 4.5.4.5 naming errors
- Most couldn't name them. Overflow ≠ stack overflow.

### Q06.4 (1) · 4.5.4.7 more precision, same bits
- Take bits from the exponent for the mantissa, or imply the bit next to
  the point (it is always the opposite of the sign bit) to gain one.

### Q07.3 (10) · 4.7.3.5 assembly: byte → two ASCII hex codes
- The hardest assembly task on this spec so far. Traps:
  - operands written in binary;
  - a missing `#` for immediate values;
  - AND with 240 but no LSR #4 afterwards;
  - code after a branch target runs on into the next label, adding a
    second constant (55 then 48) by accident.
- Practise with AQA's own instruction set before the exam.

### Q08.1 (1) · 4.11.1 velocity
- It means data arriving and needing processing **very** fast — beyond
  what a traditional relational system could keep up with.

### Q08.3 (2) · 4.12 why functional code distributes well
- Weak. Give the features with their effect: **immutable** data and **no
  side effects**, so pieces can run on different servers in any order.
  A single word ("immutable") was not enough.

### Q09.3 (4) · 4.6.5.1 Boolean simplification
- The two traps again: B̄ + B → 1 too early (AND before OR); cancelling
  NOTs that cover different parts of the expression instead of applying
  De Morgan.

### Q10.2 (1) · 4.9.1.2 synchronous transmission
- Poor. The clocks are **kept** synchronised, or a clock signal travels
  with the data.

### Q10.3 (1) · 4.5.5.3 limits of parity
- An **even number of flipped bits** goes undetected; errors are found,
  never corrected. "Multi-bit errors" is wrong (odd counts are caught).

### Q11.1 (3) · 4.9.4.1 the transport layer
- Most gave "splits into packets" only. Add port numbers, end-to-end
  connection, sequencing. Common error: describing the network layer.

### Q11.2 (1) · 4.9.3.1 gateway vs router
- Few knew: a gateway **translates between protocols** when networks
  differ.

### Q11.4 (2) · 4.9.4.2 well-known ports
- The second mark: the sender starts the connection, so the server's
  port has to be fixed and known.

### Q11.5 (6) · 4.9.3.2 asymmetric encryption and digital signatures
- Traps: forgetting that **each** party has its own key pair; using the
  wrong key at a step; "compare the digest with the message" — compare
  the decrypted digest with a **recomputed** digest of the message.

### Q12.1 (3) · 4.12.3.1 tracing a recursive function
- Base case and arguments were fine; combining the returned values on the
  way back up was where marks went.
