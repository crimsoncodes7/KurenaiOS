# KurenaiOS agent contract

This is the short, operational contract for repository work. Read `CLAUDE.md` for
the complete architecture and numbered invariants, and `PROGRESS.md` for the
current release state.

## Scope and working-tree safety

The whole repository is editable except generated outputs and explicitly gated
assets. There is no active agent ownership split.

- Inspect the branch, status and existing changes before editing.
- Preserve unrelated user work. Never stage, discard, move or “clean up” files
  outside the task.
- Do not rewrite shared history, force-push or commit directly to a protected
  branch unless the user explicitly requested that workflow.
- Keep commits scoped and report every changed shared file.
- Secrets belong in local environment files or platform secret stores, never Git,
  logs, backups or deployed static assets.

## Generated and gated files

Never hand-edit:

- `js/data/compsci.js`
- `js/data/maths.js`
- `js/data/it.js`

They are generated by the parsers and `tools/gen_data.py`. Use
`python3 tools/gen_data.py --format-existing` only for a payload-preserving layout
pass; it must not alter specification wording.

Live2D/Cubism material is release-gated. The checked-in adapter and Krita scaffold
may be maintained, but no SDK, Core, model, texture or authored rig output may be
committed or deployed until `LICENSE_REQUEST.md` answers the AI/chatbot licence
classification in writing. Do not touch unrelated `art-source/`/Krita work.

## Non-negotiable architecture

- There is no bundler. `index.html` script order and the global `KOS` namespace are
  runtime contracts.
- Navigate with `KOS.show()`. `router.js` owns browser hash history;
  `KOS.rerender()` is the no-history redraw path. Never replace `#main` directly.
- State changes pass through the owning store/normaliser. Do not create duplicate
  assignment, reminder, calendar, Collection-progress or reward records.
- Sessions are the sole source of streaks, XP, HP and gold. Core revision and
  Focus never lock. One deliberate action earns at most one reward event.
- Local persistence remains authoritative; cloud/provider sync cannot be required
  for normal app use.
- Provider credentials, Supabase sessions, media kv/audit logs and other private
  records never enter global search or full backups.

## UI, accessibility and responsive rules

- Use `KOS.ui.openDialog()` for every modal. Reuse `KOS.ui.tabs`, `emptyState`,
  `statTile`, `scroller`, `pageHeader`, `sectionHeader` and `num` before creating a
  variant.
- Use the established class names and root design tokens. Dawn and Dusk must retain
  equivalent hierarchy.
- Five breakpoints only: 1240, 1080, 860, 700 and 560 pixels. Write a component's
  media tiers widest-first and solve other collapse needs intrinsically.
- `KOS.a11y.announce()` is the only live-region route. Prefer native elements,
  provide real accessible names and avoid overlapping invisible hit targets.
- Mobile presentation moves canonical controls into sheets and restores them; it
  does not clone search, routing, filters or data logic. JS-dependent hiding must
  retain a usable unenhanced fallback.
- Horizontal scrolling is declared through the shared scroller contract. Preserve
  the compact section navigation landmark inside its one external scroller shell.
- `KOS.imageCrop` is the single image-positioning workflow. Source and crop metadata
  stay separate; cancel/reset do not write.

## Domain rules

### Study and labs

- `KOS_CONTENT` keys map only to visible specification leaves and follow
  `js/core/content.js`. Use `cs-datastructures.js` as the depth reference.
- Callouts require two closing braces. Validate every edited JS file with
  `node --check`.
- Simulations mount inline and auto-wire by `subject` + `ref`; use `WIRE` only for
  extra refs. Worked generators use `GENWIRE` and must be fuzz-safe.
- The specification spine is Study's only section list. Topic pages keep one
  header, one study-navigation row and one inspector/state surface.
- Attachments are optional and must be guarded by `KOS.attach.available()`.

### Governor, Focus and organisation

- Log completed activity through `KOS.sessions.log()`; never write rewards or
  streaks directly.
- Focus payment uses `KOS.governor.focusAward()` and occurs before the completion
  review. Review annotates the existing session; reload recovery returns paused
  without a penalty.
- Calendar recurrence is computed from one event. Assignment/reminder calendar
  chips and countdowns are derived reads, never copied events.
- The integrated weekly plan (`js/core/pacing.js`) is a one-time import that now
  lives in `state.pacing`. It reads study progress through linked spec leaves and
  writes none, performs no network request, and never logs a session. A plan row
  with no linked leaf stays unlinked rather than pointing at a near-enough one.
- Plan writes go through `KOS.pacing`: a row always belongs to an existing week,
  its week number is derived from that week, a week move re-points its rows, and
  a week delete refuses to take rows with it unless asked. The braid draws one
  branch per shared spec point and nothing it cannot evidence.
- Event writes pass through `KOS.calendar.normalise()`; alerts remain per-event.

### Collection and sync

- `mediadb.normalise()` is the media schema gate. A new query axis needs a version,
  migration and index; pull merge preserves manual data and crop/source pairs.
- Vaults use indexed reads and 60-entry lazy batches. Editors register through
  `KOS.mediaEditors`; do not replace the dispatcher.
- Push payloads are narrowly limited to list state/progress/volumes/non-zero score.
  Games never push; browser code never calls Steam directly.
- Planner performs no network or Governor work. Goals record idempotent
  activity-only completion and never create a second reward.
- Cloud sync is replication outside Governor/provider push. Use stable `syncId` /
  `fileId`, tombstones and server timestamps; never client-clock conflict logic.

## Common failure modes

- `el("textarea", {value: ...})` sets an ignored attribute; assign `.value` after
  creation.
- A card containing a select/button is not itself an ARIA button. Make its title a
  real button or use `KOS.a11y.activate()` for a genuine custom leaf.
- A placeholder is not an accessible name, and `title="null"` is not harmless.
- A stacking context traps child z-index. Use the shared `--z-*` scale and inspect
  ancestors before changing a floating surface.
- Do not render an entire vault or search result domain to “make filtering easy.”
- A chart without enough evidence needs a low-data explanation, not decoration.
- Never add a sixth media breakpoint or a one-off hard-coded palette/shadow.

## Verification

Install test-only dependencies once:

```sh
npm install jsdom fake-indexeddb
```

All 49 smoke suites are the release gate:

```sh
for i in "" {2..49}; do node "tools/smoke${i}.test.js"; done
```

Also run:

- `node --check <edited.js>` for every changed JavaScript file;
- `node tools/responsive_audit.mjs --seed` plus screenshots after responsive or
  shared-component changes;
- `node tools/visual_audit.mjs` after image, hero, chart or broad visual changes;
- `tools/deploy_pages.sh --stage` before every production upload.

An empty-state screenshot is not a responsive proof. Use dense seeded data, test
both themes and inspect interaction states that geometry probes cannot see.
